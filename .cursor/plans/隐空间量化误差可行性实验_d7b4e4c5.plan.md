# 隐空间量化误差可行性实验 (Proof of Concept)

为了向导师证明“利用连续隐向量 $z$ 与离散码字 $e_k$ 的距离（量化残差）能够有效识别损坏动作”，我们将编写一个直观的测试和可视化脚本 `test_latent_distance.py`。

## 1. 实验原理

在 FSQ 的上下文中，连续向量 $z$ 经过投影和有界化后得到 `z_bounded`，而寻找最近的离散格点就是量化操作得到 `codes_level`。它们之间的差异 `diff = z_bounded - codes_level` 的平方和，就是导师提到的距离（量化误差）。
我们现有的 `detect_corrupt_utils.py` 中的 `compute_quantization_error_per_frame` 已经实现了将 token 级别的 `diff` 映射回帧级别的误差。

## 2. 测试脚本逻辑设计

我们将要在 `动作序列损坏检测/detect/` 目录下创建一个名为 `test_latent_distance.py` 的脚本。为了与你现有的批量测试工作流保持一致，该脚本将支持类似 `run_detect.py` 的命令行参数：

1. **命令行参数支持**：
  - `--motion-dir`: 动作数据所在的根目录。
  - `--good-list` / `--corrupt-list` : 要测试的正常动作与损坏动作序列列表文件。
  - `--ckpt`: 预训练全身 FSQ 模型 (`fsq_net_6000000.pth`) 路径。
  - `--gt-csv`: 真实的损坏区间标注文件 (ground_truth_intervals.csv)。
  - `--output-csv`: 输出详细分析结果和统计数据的 CSV 文件路径。
  - `--visualize-num`: 控制需要生成并保存曲线对比图的样本数量。
  - `--frame-level`: 表明进行帧级别的损坏检测（量化误差计算）。
2. **批量加载与帧级量化误差计算**：
  - 使用现有的 `load_detector` 加载全身 FSQ 模型。
  - 遍历列表文件，成对读取（或分别读取）正常动作 `.npy` 和带局部损坏的 `_corrupt.npy`。
  - 分别调用 `compute_quantization_error_per_frame`，获取仅在隐空间计算的帧级量化误差数组（长度为 $T$），**彻底绕过 Decoder**。
3. **进行数据分析与结果输出 (--output-csv)**：
  - 将计算得到的量化误差与 `--gt-csv` 提供的真实标注（GT）进行比对分析。计算是否可以使用一个therehold值来获取最佳的准确率与召回率
  - 将分析指标（如：预测的异常区间、量化误差的峰值/均值、与 GT 的重合率等）格式化后写入 `--output-csv` 文件中，替代简单的 txt 输出。
  - 通过这份详细的 CSV 数据表，可以直接量化地确认：在隐空间中依靠量化误差定位局部损坏的准确率和可行性。
4. **曲线对比可视化 (--visualize-num)**：
  - 取前 N 个 (`--visualize-num`) 测试对，使用 `matplotlib` 绘制折线图并保存。
  - 横坐标是时间（帧），纵坐标是**量化误差（距离）**。
  - **蓝线**代表正常动作的误差，**红线**代表损坏动作的误差。
  - 在图的背景上，根据 `--gt-csv`，用浅黄色高亮标出**真实的局部损坏区间**，直观验证红线的尖峰 (Spike) 是否完美落在高亮区间内。

## 3. 预期实验结果

如果导师的猜想（以及代码的逻辑）是正确的，你将会看到：

- **蓝线（正常）**：全程保持在一个较低且平稳的值附近。
- **红线（损坏）**：在正常的帧区间内与蓝线重合，但在高亮的“损坏区间”内，红线会**急剧飙升，出现明显的峰值 (Spike)**。
